# @bot-wa/core

## 2.0.0-alpha.2

### Minor Changes

- 2e16743: `@bot-wa/ai`: native tool / function calling. `aiPlugin({ tools })` maps each tool (description, JSON Schema or `safeParse` schema, handler, `confirm`) to Anthropic, OpenAI (and OpenAI-compatible presets), Gemini and Ollama, with a multi-step loop (`maxSteps`), per-tool timeouts, errors returned to the model, human confirmation for `confirm: true` tools through the conversation runtime (no FIFO deadlock) and audit events (`onToolEvent`, `bot.on('ai.tool')`). New exports: `defineTool`, `confirmWith`, `runToolLoop`, `AIToolCancelledError` and the tool types; `MockAIProvider` can script tool calls.
  
  `@bot-wa/core`: `bot.enterConversation(nameOrHandler, ctx)` enters a conversation programmatically, fire-and-forget, so a handler can start one and release the chat queue; it returns a promise that settles (never rejects) once the conversation has ended.
- 397c2be: Public API coherence (see `docs/api-review.md`), all backwards compatible:
  
  - Export types that public signatures already referenced: `InboundListener`, `StopOptions`, `ConversationTarget`, `WaitMediaType`, `UserDataStore`, `PacerLogger`, `FormFieldBase`, `JsonValue` (main entry; it was only in `/testing`), and `MockIncomingOptions` from `@bot-wa/core/testing`.
  - One duration grammar everywhere: the internal parser (flows, reply delays, broadcast, dedupe, conversations) now accepts what the exported `parseDuration` did (`'1d'`, `'1w'`, `'5 minutes'`, digit strings). Timer-backed options (flow, wait, form and conversation timeouts, `MemoryStore.autoSaveInterval`, `bot.stop({ timeout })`) throw `RangeError` above about 24 days, the most a Node timer can hold.
  - `bot.stop({ timeout })` and `MemoryStore({ autoSaveInterval })` also accept a duration string; `bot.send()` accepts a plain string like `sendTo()`/`broadcast()`; `bot.onError()` takes an optional `priority` like `before()`/`after()`.
  - Fix: `bot.hook()` called from a plugin is now removed by `unplug()`, and `onError` inside a plugin honours its priority.
  - `ConversationError` and `ProviderError` subclasses carry their class `name`.
  - `HookEvent` keeps editor autocomplete for the built-in event names.
  - Deprecate `ctx.replyWithTyping()` in favour of `ctx.reply(text, { typing: true })`.
- 0a2291f: Breaking (alpha): hook contexts are typed by the event name and `Plugin.install` must be synchronous. `HookHandler<TCtx = unknown>` (was `any`); `bot.before/after/onError/hook` infer the context through the new, augmentable `HookContextMap` (`message` → `MessageContext`, `send` → the new `SendHookContext`, `call`, `reaction`, `poll`, `group`, `presence`, `status`, `connection`), so `bot.before('message', (ctx, next) => ctx.body)` typechecks without an annotation; a custom event's context is `unknown` unless the handler annotates it, a type argument is passed or `HookContextMap` is augmented. New `HookErrorHandler` (`onError` receives `(ctx, error)`), `HookContextOf`, `HookBeforeContext`, `AnyHookHandler`; `HookRegistration` is exported. A `HookHandler<MessageContext>` registered on `'send'` no longer compiles. `PluginSpec.install` returns `void | SyncInstallError`: an `async install` (or one returning a promise or a value) is a compile error whose message explains why; at runtime a rejected promise still reaches the `'error'` event. `bot.triggerFlow(id, target, { data })` takes `data` like `bot.trigger()`; `state` stays as a deprecated alias and passing both throws a `TypeError`. `@internal` symbols are stripped from the published types (`stripInternal`).
- ee5777c: **Breaking:** a `before` hook that returns without calling `next()` now stops the event exactly like `abort()` (the message is not routed, the send is skipped, the provider event is not emitted). It used to skip only the remaining `before` hooks while the message was still routed. Observer and rewriting hooks must end with `await next()`.
- 522bcca: Behaviour changes:
  
  - Handler errors always reach the bot `'error'` event, even without an `onError('message')` hook.
  - Inbound dedupe is on by default: a redelivered message with the same `chatId` + id and body is handled once (`dedupe: false` opts out).
  - `slashCommandsPlugin`: `/reset` also re-arms `WELCOME`; `/cancel` only cancels.
  - `bot.onType()` / `bot.onImage()`… move to specificity tier 2 (same relative order; multi-type triggers sit at 1).
  - `MessageContext` gains the required `user` and `handoff()` members and the optional `call`.
  - `deleteSubject()` also forgets the subject chat's handoff and re-arms its `WELCOME`.
- a33cb08: Calls from blacklisted or non-whitelisted senders/chats, or into a handed-off chat, are now fully blocked like a message: no `before`/`after('call')` hooks, no `bot.on('call')` event and no `CALL` trigger. Blocked calls count in `metrics().dropped.blocked` / `dropped.handoff` and are debug-logged.
- 9cb6621: Bot operations: `bot.broadcast(chatIds, content, { batchSize, delayBetween, concurrency, maxRetries, onProgress, onFail, signal })` now batches, honours `RateLimitedError.retryAfterMs` (pausing every worker) and is cancellable (by `signal` or `bot.stop()`); it resolves `{ total, sent, failed, skipped, errors, messages, cancelled, pending }` (breaking: `sent`/`failed` are now counts — the accepted sends moved to `messages`, the failures to `errors`). New `bot.trigger(name, { chatId, userId?, isGroup?, data?, ifActive? })` starts a registered flow/conversation with `c.state` seeded from `data`, through the access-list and handoff gates and the chat's FIFO queue (safe to `await` from a handler of the same chat). New `bot.metrics()` / `bot.resetMetrics()` runtime counters, `'conversation:started'` / `'conversation:ended'` events (`{ id, name, chatId, userId, key, outcome, completed, durationMs, goto? }`; `id` pairs an end with its start, and a replaced conversation ends before its replacement starts) and a dependency-free Prometheus exporter `toPrometheus(snapshot, { prefix?, labels? })`.
- 99251ef: Opt-in multi-replica coordination (`BotConfig.coordination`). A `Coordinator` (exported contract, with `MemoryCoordinator`/`MemoryCoordinationHub` as the in-process reference) gives each chat a cross-replica FIFO: the Dispatcher reserves a ticket per message at enqueue time and processes it only while holding the chat's turn, held until the conversation it fed settles. A message that cannot get its turn is dropped and reported (`CoordinationUnavailableError`); sends after a lost turn reject with `LeaseLostError`. A `.persistent()` flow continues on another replica from its checkpoint, the waking message answering the pending question. New optional `ProviderCapabilities.exclusiveSession` and `coordination.providerSession`: exclusive transports start only on the elected replica (`ProviderNotLeaderError` on standbys). New events `'coordination:leader'`, `'coordination:follower'`, `'coordination:lease-lost'`; `MockProvider` gains `exclusiveSession`, `starts` and `stops`. Conversation timers (wait timeouts, `c.idle()`) run under the chat's turn; a handover answers the pending question only when the checkpoint says the flow was parked on its step's first wait (new optional `FlowCheckpoint.parked`); a step longer than `settleMs` is suspended before the turn is released; `coordination.providerDownMs` makes a leader with a dead transport step down. Without `coordination` nothing changes.
- 7cc66b2: Cron time zones in the scheduler (opt-in). `bot.schedule(cron, { timeZone: 'America/Bogota' }, fn)` (new `CronTaskOptions` type), `DurableTaskOptions.timeZone` for durable tasks and `SchedulerOptions.timeZone` (`BotConfig.scheduler.timeZone`) as the default zone of every cron task; `'local'` is the process zone. Built on `Intl` only. Daylight-saving policy: a fixed-hour slot in a skipped hour runs once, shifted forward by the gap; in a repeated hour it runs once, at the first occurrence; wildcard-hour slots follow the real clock. Durable tasks store the zone in their spec (`TZ=<zone> <cron>`), so tasks without a zone keep their stored spec unchanged. `cronNextRun(expr, from, timeZone?)` takes the zone, and `ScheduledTask.timeZone` reports it. An unknown zone throws a `RangeError` at registration; `every`/`delay` reject `timeZone`. Without `timeZone`, nothing changes.
- 39a8149: `MessageContext.defaultLang` (optional): the bot default locale, whatever `ctx.lang` resolved to, so plugins that ship texts for only a few languages have a fallback.
- 40fdab4: Durable message processing, opt-in through `BotConfig.durability`. Without the key nothing changes. Inbound messages and interactions are journaled in an inbox before dispatch and acknowledged once their conversation steps settle; after a crash they are replayed on the next `start()`. Every send goes through an outbox under an idempotency key (`SendOptions.idempotencyKey`, or derived from the inbound message being handled), so a replay never re-sends a reply that already went out. Retries use backoff and honour `RateLimitedError`; there is a dead-letter queue, `SendDeferredError` once `outbox.inlineMaxMs` runs out, leases with fencing tokens (`StaleLeaseError`) and an `onAmbiguous` policy. New API: `bot.durability`, `bot.enqueue()`, and the `'durability:dead'` / `'durability:ambiguous'` events. Two backends ship in core, `MemoryDurability` (default) and `FileDurability`; store packages implement the `DurableKv` seam through `KvDurability`. `FlowCheckpoint` gains the optional `inboundId` and `cause` fields. `@bot-wa/core/testing` adds `crashable()` and `CrashableProvider`. Several bots can share one backend: each works in the view of its namespace (`DurabilityBackend.scope()`, `bot.durability.scope`), so claims, replays and explicit idempotency keys are per bot. On a shared backend the default `instanceId` is unique per boot (own leases are reclaimed early only with an explicit id or a single-process backend). A message that keeps killing the process is dead-lettered after `inbox.maxAttempts` instead of crash-looping, sends in flight extend their outbox lease (`OutboxJournal.extend`), live events of one chat keep their arrival order while the inbox append runs, and a replay whose n-th send has different content than the recorded one is sent under a new key (`outbox.onDiverged: 'send' | 'skip'`, metric `outboxDiverged`). With `BotConfig.coordination`, the outbox sweeper only calls the transport on a replica that holds the provider session (a standby's attempt is refused with `ProviderNotLeaderError` and retried by the leader), and the shared inbox journal deduplicates redeliveries across replicas. A live send whose outbox record the sweeper claims meanwhile follows that delivery instead of throwing `SendDeferredError`.
- 4bbd0ad: Add a dynamic flow registry to `Bot`: `registerFlow()`, `unregisterFlow()`, `replaceFlow()` (hot-swap), `hasFlow()`, `listFlows()`, `triggerFlow()` (start a flow proactively in a chat) and `listConversations()`. New exported types `RegisteredFlowInfo`, `FlowTriggerTarget` and `FlowTriggerOptions`.
- 231cbd2: Flow DSL: `.use(subFlow)` runs a flow inline and returns to the parent with merged state; `choose()` options accept `goto` to leave for another conversation (e.g. back to the main menu); `.guard(check, message | { redirect, message })`; zod-compatible `schema` (any `safeParse()` object) in `.ask()`, `c.ask()` and `c.waitText()`, which resolve with the parsed value; `.media(kind, source, caption?, opts?)` for image/video/audio/voice/document/sticker/location (the legacy `.media(source, caption?)` still sends an image, now compiled as a `media` step); `{ delay }` on say/ask/choose/media plus a `.delay()` step; and typed flow state (`flow<S>()`, `.ask(…, 'key', { schema })` infers `c.state.key`). `bot.describe()` and `bot.lint()` understand the new steps (guard redirects and option gotos are checked like `goto`).
- ca25eb7: `flow().form()` defaults are localizable: the field-by-field hints, the skip word, the native "fill in the form" reminder and every validation error now come from the built-in `core.form.*` catalog (`CORE_MESSAGES.form*`, `es` and `en`) in the subject's `ctx.lang`. A `schema` rejection without its own message uses `core.wait.invalid` (`DEFAULT_SCHEMA_MESSAGE` is deprecated). `parseFieldAnswer()` and `validateFormValues()` take an optional translator (default: Spanish, unchanged output). Multiselect answers also accept `and` as a separator.
- 18958c6: Add golden transcripts: `recordTranscript` (recording `IProvider` wrapper), `transcriptFromStore`/`transcriptFromMessages` (from the store message log), `redactTranscript` (stable `<user:N>`/`<email:N>`/`<phone:N>` placeholders), a versioned JSON format (`parseTranscript`/`serializeTranscript`), and `replayTranscript`/`assertTranscript` in `@bot-wa/core/testing` with expected-vs-actual diffs and tolerance options (masks, ids, timestamps, content fields, ordering). Redaction applies patterns to inbound text only by default (bot-printed prices/dates stay comparable; `outboundPatterns` + replay `redact` opt in), replaces display names with `<name:N>` (replayed as push name), and can emit format-valid `surrogates`. `transcriptFromStore` accepts a `Bot` and reads group kinds from the store; live inbound timestamps with second precision are persisted with the receive time so the message log orders them correctly against replies. `RecordingProvider` keeps a bounded buffer (`maxTurns`, default 10 000).
- 40ec0bd: i18n: new `locales` option (`BotConfig.i18n` / `bot.locale({ locales })`), an allow-list of the languages the bot serves. A stored preference, provider-reported or detected language outside it is ignored (resolution falls back to `defaultLocale`, always served) and `ctx.setLang()` refuses it; `'en'` also serves `'en-GB'`. Use `locales: ['en']` to pin a single-language bot so a client in another language does not get built-in texts in its language around your content. Also, an update whose provider reports no language (Telegram's `language_code` is optional) now reuses the last language reported for the same sender (in memory, bounded) instead of flipping the chat to the default between turns.
- fd07c8c: Native i18n: `bot.locale(code, messages)` / `bot.locale(options)` registry with nested keys, `{param}` interpolation and plural forms; `ctx.t()`, `ctx.lang`, `ctx.setLang()` (persisted to `ctx.user`; only accepts a code a registered locale serves and rejects while i18n is off), `c.t()` / `c.lang` in conversations, `bot.t()` / `bot.langOf()`. Language resolution (each candidate must be served by a registered locale): `ctx.user` preference → provider-reported language (`SenderInfo.language` or `platformData.languageCode`) → `i18n.detect` → default. Built-in core messages (timeouts, retries, errors, wait validation, slash commands) are localizable under `core.*` with `es` and `en` defaults; without any i18n configuration bots keep their Spanish defaults.

- 64fb59f: Add automatic typing indicator (`BotConfig.typing`), per-reply pacing (`ctx.reply(text, { typing, delay, cancelIf })` on `reply`/`say`/`answer`/`text`/`quote`), `ctx.edit()` for the context's own last reply or a given ref (native via `provider.editMessage`, falling back to a new message in the ref's chat), `ctx.react(emoji, target?)` that resolves `skipped` on providers without reaction support, and `ctx.supports(feature)` reporting `native` / `degraded` / `unsupported`. Baileys journals only the media content (CDN url, direct path, media key and hashes; no thumbnail, caption or quoted context) plus the message key that re-upload requests need. It skips view-once media unless `durableMedia: { viewOnce: true }` is set, and it returns the cached original message while it is still in memory. Cloud API journals the media id and Telegram the `file_id`. None of them journals credentials, and each validates the stored value when it reads it back.
- 2232f88: Native form labels follow the user's language. `ctx.form()` / `flow().form()` fill a missing `cta`, `submitLabel` and (without `intro`/`title`) body from the new `core.form.cta`, `core.form.submit` and `core.form.body` catalog entries (`es`/`en`) in `ctx.lang`, through the exported `withFormDefaults()`. `@bot-wa/meta` no longer hard-codes Spanish: its fallbacks use the same catalog and `toFlowJson(def, { lang })` (also `publishForm(def, { flowJson: { lang } })`) picks the language of the published Flow's default submit label (default `'es'`, unchanged).
- 27620ef: Add a WhatsApp Cloud API 24 h customer-service window manager (`sessionWindow` option, `SessionWindowManager`, pluggable `SessionWindowStore`): reopen closed chats with an approved template and retry the original send when the user replies. Status events now carry the normalized `pricing`/`conversation` objects in `DeliveryStatus.platformData` (new optional field in core), and `provider.usage` aggregates per-chat/per-category usage and estimated cost. Window state is scoped per business number (`phoneNumberId`; shared managers via `forScope()`), and media is uploaded once before queueing so retries never re-read a drained stream or keep media bytes in memory.
- e4574e6: Tracing hooks, opt-in through `BotConfig.telemetry`. Without the key nothing changes (no span code runs). With a `BotTracer` (OpenTelemetry through the private `@bot-wa/otel`, or your own) the bot emits spans for inbound events, persistence, dispatch (queue wait, routing stage), handlers, conversation turns (one per stretch between waits; flow steps as events), triggers, broadcasts, pacing and sends, with chat/sender/message ids hashed by default (`ids: 'hash' | 'raw' | 'omit'`, `idKey`) and never message bodies, prompts or error messages (unless `errorMessages: true`). A throwing tracer never breaks the bot. New API: `bot.tracing`, the `BotTracer`/`BotTracing`/`BotSpan`/`TelemetryConfig` types, `TRACE_ATTR`, `SPAN_NAMES`, `noopTracer`, `NOOP_TRACING`, `errorTypeOf`, and `createRecordingTracer()` in `@bot-wa/core/testing`. `Dispatcher.conversationMatcher()` takes an optional `{ flow }`.

Model calls become `chat {model}` spans with OpenTelemetry GenAI attributes (models, token usage, finish reason, purpose; a timeout is `error.type = timeout`), tool calls `execute_tool {name}` spans with their outcome, and RAG retrieval a `bot.ai.retrieve` span; no prompts, completions, arguments or results are recorded. `GenerateInput.onStreamEnd` also reports `usage` when the provider streams it (Anthropic, Gemini).
- b95b523: Opt-in runtime hardening: `BotConfig.echoFilter` drops inbound echoes of the bot's own sends (before access lists, dedupe and the journal; counted in `metrics().dropped.echo`); `IStore.setCheckpointIf`/`clearCheckpointIf` (optional CAS used with `coordination`, with `FlowCheckpoint.revision`) so a frozen replica cannot overwrite the new owner's checkpoint; `FileDurability.open(path, { appendLog })` appends deltas to `<path>.log` with periodic compaction instead of rewriting the snapshot.
- 5196990: Durable scheduler tasks (opt-in). `bot.schedule/every/delay(spec, { id, missed, maxCatchUp, leaseMs }, (run) => ...)` persists the next run in a `ScheduleStore` (`BotConfig.scheduler.store`, in memory by default), applies a missed-run policy (`skip`, `run-once` or `catch-up`) to slots no replica ran in time and claims each occurrence under a fenced lease so replicas never run it concurrently (at least once; `run.occurrenceKey` is an idempotency key). `bot.forgetTask(id)` deletes a stored schedule (orphans, one-shot tombstones); fencing tokens never go backwards for an id, even across deletes. Optional scheduler leadership (`scheduler.lease`, type `SchedulerLease`): a fenced `LeaseProvider` (`MemoryLeaseProvider`, new contract) or the multi-replica `Coordinator`, which a bot with `BotConfig.coordination` uses by default. `@bot-wa/sqlite-store` adds `SQLiteStore#schedules()` (and `SQLiteScheduleStore`, whose constructor takes a structural `SQLiteDatabaseLike`, so consumers need no `@types/better-sqlite3`); `@bot-wa/redis-store` adds `RedisStore#schedules()` and the fenced `RedisStore#leases()`. Tasks without `id` behave as before.
- 2c4f9f0: `messageKey(ref)` percent-escapes `%` and `:` in the chat id and the message id, so ids that contain `:` (Twilio's `whatsapp:+1…` chat ids) no longer collide; keys of ids without `:` or `%` are unchanged. New `legacyMessageKey(ref)` returns the old unescaped key. SQLite and Redis stores write the new key, still read and delete rows stored under the legacy key (checking the stored `ref` is the requested message, since a legacy key can be another message's new key), and drop the legacy copy when a message is saved again — no manual migration.
- efb1fa6: Native streaming of long/AI replies with `ctx.stream(source, opts)`. The strategy comes from the new `ProviderCapabilities.streaming` field (`'draft' | 'edit' | 'none'`): native drafts (Telegram `sendMessageDraft`, with `can_stop`/`keep_on_stop`), throttled message edits (Discord, Telegram groups) or sentence chunks with typing (WhatsApp). Updates are throttled, cancellation is supported (`signal`, the user's stop button) and no message exceeds `maxTextLength`. New exports: `streamText`, `resolveStreamStrategy`, `splitMessage`, `findSplitPoint` and their types; `IProvider.sendDraft`; `MockProvider({ streaming })`. `@bot-wa/ai` gains `AIClient.streamReplyInChat()` and the `stream` option for the autoresponder. The Telegram long-poll now also asks for `stopped_message_generation` updates. Live edits and drafts run the `before('send')` hooks (payload `stream: 'draft' | 'edit'`) and the message log keeps the final edited text; rate-limited edits back off for `retryAfterMs`; `onCancel: 'discard'` deletes the live message when the transport can. The streamed autoreply honours refusals (`refusalMessage`, not stored), replies `errorMessage` on an empty answer and, with `onCancel: 'discard'`, keeps a cancelled answer out of the context.
- 4fc0560: Add native forms: `flow().form(definition, opts)` collects typed fields (text, number, email, date, select, multiselect, opt-in) with validation. Providers with the new `capabilities.forms: 'native'` receive an `OutboundContent` of kind `'form'` and reply with `'form'` inbound messages (`formReplyBody()` / `parseFormReply()`); every other provider gets field-by-field questions. `describe()` draws `form` nodes and `lint()` checks their timeouts and `c.state` key collisions. `@bot-wa/meta` renders forms as static WhatsApp Flows (`toFlowJson`, `toFlowMessage`, `publishForm()`, `config.flows`) and turns `nfm_reply` webhooks into form replies. Other providers reject the `form` kind with `UnsupportedContentError`. The new optional `IProvider.canRenderForm(form, { nativeId })` (exposed as `ctx.canRenderForm()`) lets a native provider say it has no native form for a definition; `CloudAPIProvider` implements it, so a form without a mapped Flow is asked field by field without first sending (and failing) a form message. Ambiguous grouped numbers (`1.500`, `1,500`) are rejected instead of being read as 1.5.

### Patch Changes

- ddfb1e9: The blacklist/whitelist now run before inbound dedupe: a blocked message or interaction is no longer recorded as seen, so a redelivery after un-blocking is processed. While still blocked, every delivery counts in `metrics().dropped.blocked` (never `duplicate`).
- 588fa34: `ctx.typing()`, `ctx.recording()`, `ctx.replyWithTyping()` and the `ctx.stream()` indicator are best-effort: a rejecting or throwing `provider.typing()` is logged at debug and ignored, so a failing indicator never aborts the reply after it. The Bot's default logger (no `logger`, no `debug`) now logs at `warn` instead of `error`, so warnings from plugins and handlers (e.g. a failed AI autoreply) are visible without `debug: true`.
- 909fa96: `BotConfig.logger` now accepts any `LoggerLike`, not just pino: a pino-shaped logger passes through untouched and any other one (`console`, `{ debug, info, warn, error }`) is adapted (`child()` forwards or reuses the logger, `trace`/`fatal` are no-ops). Before, a `LoggerLike` without `child` compiled but threw in the `Bot` constructor. New internal seam `toBotLogger()` (`core/src/core/bot/logger.ts`).
- 31fcc2e: The `Bot` omits `undefined` fields from its chat and contact upserts, so a message without a display name (or chat name) no longer erases the one already stored. `IStore.upsertChat` / `upsertContact` document the contract: an own field set to `undefined` unsets it, so partial upserts must omit unknown fields.
- f8c1d4f: `FileDurability`: a second `open()` of the same file in the same process is refused (`already open in this process`) until the first journal is closed; before, the lock with our own pid was taken and the two instances overwrote each other's snapshots. A lock file with our pid and no open journal in this process (a restarted container reusing pids) and one of a dead process are still taken over. An empty or garbled lock younger than 10 s is no longer treated as stale: `open()` waits up to the new `lockWaitMs` option (default 2 s). `close()` is idempotent, waits for pending writes and makes later writes reject; new `locked` getter.
- 1a81406: `MemoryStore` documents its default cap of 1000 messages per chat (RAM only; the persistent stores stay unbounded unless configured), accepts `maxMessagesPerChat: Infinity` to disable it, and rejects a negative, fractional or `NaN` cap with a `RangeError`.
- 310db8d: `MockProvider.editMessage` / `deleteMessage` / `sendDraft` are real class methods again, so a subclass that defines them as methods typechecks (no TS2425). The new `supports: { edit, delete, drafts }` option chooses which ones are exposed (defaults follow `streaming`); a disabled one reads `undefined` on the instance so the bot treats it as unsupported, and an explicit `false` also hides a subclass override.
- 6ea4442: Provider events (`reaction`, `poll`, `group`, `presence`, `status`, `call`) follow the same hook contract as `message` and `send`: a `before` hook that aborts now suppresses the `after` hooks and the `bot.on(...)` event, which used to run anyway.
- 634993f: `bot.stop()` no longer leaves work or timers behind under load: `stop({ drain: true })` clears its deadline timer when the sends finish early, paced replies still waiting (`BotConfig.typing`, `{ delay }`) are woken and dropped at once, running `ctx.stream()`s are cancelled and send, edit or delete nothing more once the provider stops (new optional `StreamTarget.shutdown` signal), a message still queued for a chat is dropped instead of starting a conversation after the stop, and the conversation runtime no longer keeps a shutdown flag per aborted non-persistent conversation. `bot.deleteSubject()` also forgets the language the provider reported for the subject. New `ConversationRuntime.close()`/`open()`/`isClosed()` and `I18n.forget()`.
- 23371fb: Fix races and lifecycle edge cases: a matcher registered while a message is being routed no longer makes another matcher run twice; entering a conversation discards that key's dormant checkpoint (the stale flow used to resume on the next message); `start()` reloads dormant checkpoints from the store instead of merging them with the pre-`stop()` ones; `bot.deleteSubject()` cancels the subject's live and dormant conversations; a `stop()`/`start()` while a scheduled task runs no longer forks its timer chain or re-runs a `delay()` task; delivery receipts never move a message's status backwards (a `failed` after `delivered` still wins, and a receipt's error is always kept) and are written in order per message; the store clear of a replaced dormant checkpoint can no longer land after, and wipe, the new persistent flow's first checkpoint; the scheduler no longer fires runs more than ~24.8 days away in a tight loop (quarterly crons, `delay('40d')`), it waits in chunks within the `setTimeout` limit; `bot.broadcast()` before `start()` sends nothing. `bot.plug()`'s unplug now also removes conversations, flows and nested plugins registered through `ctx.bot` and calls `uninstall()` once; a throwing `install()` is rolled back and a rejected async one goes to the `'error'` event. Cron: stepped ranges (`1-5/2`) honour their upper bound, `7` means Sunday and a malformed expression throws a `TypeError` naming the field. `c.choose()` with no options throws a clear error. New `ConversationRuntime.abortWhere()`.
- ce7790f: Packaging: dependencies between `@bot-wa/*` packages are published as caret ranges (`^x.y.z`, from `workspace:^`) instead of exact versions, so npm dedupes a single `@bot-wa/core` instead of installing a second copy when one package lags a patch behind. Published READMEs use absolute GitHub links (relative links broke on npmjs.com), and `@bot-wa/core`/`@bot-wa/http` gain `repository.directory`, `homepage` and `bugs` metadata.
