Breaking (alpha): hook contexts are typed by the event name and `Plugin.install` must be synchronous. `HookHandler<TCtx = unknown>` (was `any`); `bot.before/after/onError/hook` infer the context through the new, augmentable `HookContextMap` (`message` → `MessageContext`, `send` → the new `SendHookContext`, `call`, `reaction`, `poll`, `group`, `presence`, `status`, `connection`), so `bot.before('message', (ctx, next) => ctx.body)` typechecks without an annotation; a custom event's context is `unknown` unless the handler annotates it, a type argument is passed or `HookContextMap` is augmented. New `HookErrorHandler` (`onError` receives `(ctx, error)`), `HookContextOf`, `HookBeforeContext`, `AnyHookHandler`; `HookRegistration` is exported. A `HookHandler<MessageContext>` registered on `'send'` no longer compiles. `PluginSpec.install` returns `void | SyncInstallError`: an `async install` (or one returning a promise or a value) is a compile error whose message explains why; at runtime a rejected promise still reaches the `'error'` event. `bot.triggerFlow(id, target, { data })` takes `data` like `bot.trigger()`; `state` stays as a deprecated alias and passing both throws a `TypeError`. `@internal` symbols are stripped from the published types (`stripInternal`).
